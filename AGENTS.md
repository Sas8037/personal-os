# Personal OS Agent Instructions

At the start of every task, read [COMMUNICATION-STANDARD.md](docs/development/COMMUNICATION-STANDARD.md) and [TASKS-AND-IMPROVEMENTS.md](docs/planning/TASKS-AND-IMPROVEMENTS.md). The standard defines collaboration and evidence rules; the tracker is the single task, finding and improvement record. Follow their current rules and the owner's explicit task authorization.

- Use the standard's appropriate communication template and authorization boundaries. Recommendations and tracker statuses do not replace owner decisions; separately authorized tracker updates may lag current instructions.
- Change only the single file authorized for the task. Explain dependencies on other files and propose separate tasks rather than expanding scope.
- Check the whole repository for inconsistencies and errors at task start and after implementation, with depth proportional to risk as defined in the standard.
- Report discovered issues without repairing them unless their repair is explicitly authorized.
- Provide verification evidence, material limitations and useful improvement recommendations, or explain why none are justified. Apply the standard's evidence labels accurately.
- Preserve existing staged, unstaged and untracked work. Distinguish local changes, committed changes and published changes in reports.
- When the tracker is outside the permitted file scope, report proposed tracker updates in the completion report; do not edit it alongside the authorized file.

Reference these documents rather than copying their templates, maintaining duplicate statuses or introducing additional planning documents.
